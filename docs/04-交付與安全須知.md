# 04 · 交付與安全須知（給學長 / 交付者先讀）

## ⚠️ 最重要：git 歷史會外洩原始碼

這個分支（`teaching/ais3-medical-target`）雖然**工作區只剩醫療靶機**，但它和主線共用 git 歷史——
**過去的 commit 仍完整包含發電廠等原始程式碼**。若直接把整個 repo（含 `.git/`）給學員，他們 `git log` / `git checkout` 就能還原你不想外流的內容。

**正確的交付方式：只給「檔案快照、無歷史」。** 兩種做法：

### 做法 A：`git archive` 匯出乾淨壓縮檔（最簡單）
```bash
cd factory
git archive --format=tar.gz -o /tmp/medical-target.tar.gz teaching/ais3-medical-target
# 交這個 .tar.gz 給學員即可（不含 .git、不含歷史、只有這個分支的當前檔案）
```

### 做法 B：從乾淨工作區另起全新 repo
```bash
# 在一個乾淨目錄解開快照後
git init && git add -A && git commit -m "Medical device cyber range (AIS3 teaching target)"
# 這個新 repo 的歷史只有這一個 commit，可安心給學員或推到新的遠端
```

> 交付前自我檢查：`git archive` 出來的檔案裡不該有 `powerplant`、`turbine`、`發電` 等字樣。
> 可跑：`tar tzf /tmp/medical-target.tar.gz | grep -i 'plant\|turbine'`（應為空）。
> 也可在解開後 `grep -rIn 'powerplant\|turbine\|發電'`（應為空——本分支工作區已清乾淨）。

## 這個分支移除了什麼、保留了什麼

- **移除（你的資產，不外流）**：發電廠物理模擬與攻擊偵測、分揀線/水處理/自動倉儲/高鐵的 Profile 與 3D 場景、發電廠專屬 3D 設備模型與 Sketchfab hero 模型、對應的通道/攻擊/座標定義。Go module 也已改名 `med-target`，import 不再出現 `powerplant`。
- **保留（通用框架 + 醫療內容）**：Modbus/WebSocket 伺服器、`GenericFacility` 引擎、HUD/前端骨架、兩台醫療設備 Profile、HL7/DICOM 端點、醫療 3D 場景。

## 實驗室隔離（給學員的規則）

- 只在**獨立、無外網**的實驗網段跑靶機與 fuzzer（VM/容器 + host-only 網路，或獨立 VLAN）。
- 不要把 Modbus/HL7/DICOM 埠對公網開放；靶機沒有驗證機制，等於開放控制。
- 這是模擬器：**永遠不要**把 fuzzer 指向任何真實醫療設備、醫院網路或臨床系統——即使只是「測試看看」。
- fuzz 會讓 process 承受大量畸形輸入；崩潰是預期的，重啟即可。

## 授權與倫理

- 對本靶機的一切攻擊/fuzz 皆在**授權範圍內**（這就是它的用途）。
- 學到的手法只能用於**你有明確書面授權**的系統。未授權測試真實醫材可能危及病人安全並觸法。
- 若在真實研究中發現漏洞，走**負責任揭露**：TWCERT/CC、廠商 PSIRT、或 FDA/衛福部醫材通報，給修補時間，勿公開可直接複製的 PoC。
- 這份靶機與文件的目的是**培養防禦與合規能力（IEC 62443 / IEC 80001）**，不是提供攻擊真實醫院的工具。

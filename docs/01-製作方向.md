# 01 · 靶機製作方向

這份文件說明靶機怎麼做出來的、為什麼這樣設計，以及**你們要怎麼擴充**（例如加第三台醫療設備、或加一個協定）。

## 設計理念

1. **一台設備 = 一台 PLC = 一個 Modbus Unit ID**。真實醫院裡的醫材/設備控制器就是各自獨立的節點，這裡照這個心智模型。
2. **資料驅動（data-driven）**：設備不用各寫一份程式，而是用一個 `Profile` 結構描述「暫存器映射 + 物理 + 故障規則 + 攻擊注入」，由通用引擎 `GenericFacility` 執行。加設備 = 加一個 Profile。
3. **物理讓後果看得見**：攻擊只是「把某個暫存器寫成危險值」，真正的傷害（過量、失超…）由每 100ms 的物理推進算出來，再透過 WebSocket 推給前端 3D 呈現。這樣學員能直覺看到「改一個數字 → 病人受害」。
4. **故意寬鬆**：協定端點（尤其 HL7/DICOM）刻意少驗證、對畸形輸入不崩潰但也不嚴格，方便當 fuzz 標的。

## 後端結構（`backend/`）

```
main.go                 啟動：組裝設施、開 Modbus/HL7/DICOM/HTTP、每 100ms 推進+廣播
flags.go                CTF 解鎖規則（寫對 Coil 才吐 flag）
facility/registry.go    BuildAll()：掛上要模擬的設備
simulator/
  facility.go           GenericFacility 通用引擎 + Profile 型別定義
  profiles_medical.go    ← 兩台醫療設備的 Profile（你們主要改這裡）
medproto/
  hl7.go                HL7/MLLP 伺服器（fuzz 標的）
  dicom.go              最小 DICOM 上層伺服器（fuzz 標的）
modbus/server.go        Modbus TCP 伺服器（依 Unit ID 路由，通用，不用改）
websocket/handler.go    WebSocket 廣播（通用，不用改）
```

## `Profile` 長什麼樣

`simulator/facility.go` 定義了 `Profile`，欄位：

| 欄位 | 意義 |
|------|------|
| `ID`, `Name`, `Unit` | 設施 id、顯示名、Modbus Unit ID |
| `Regs []RegChannel` | Holding Register 通道：`Key`、`Addr`、`Scale`（工程值×Scale=暫存器值）、`Default`、`Writable`（true=攻擊標的 RW，會被外部寫入鎖定；false=衍生唯讀輸出） |
| `Coils []CoilChannel` | 布林控制線圈：`Key`、`Addr`、`Default` |
| `Failures []FailureRule` | 門檻持續超限→觸發故障：`Key`(故障 id)、`Channel`(監看通道)、`Limit`、`Above`、`DelaySec` |
| `Attacks []AttackAction` | 攻擊注入：`Type`、要寫入的 `Regs`/`Coils` |
| `Annots []WriteAnnotation` | 對某暫存器寫入的可疑判定→即時警報 |
| `Physics func(state, coils, estop)` | 每 tick 推進：讀 core 值→算 derived→就地寫回 `state` map |

引擎每 100ms 會：`syncFromRegisters`（把外部 Modbus 寫入吃進 state）→ `Physics`（算衍生 + 故障指標）→ `checkFailures`（超限計時→設定 `explosionType`）→ `syncToRegisters` → 廣播 `{type:"status", facility, status}`。

`status` JSON 內含：所有通道值 + 所有線圈布林 + `isUnderAttack` + `explosionType`（故障 key 或 `"none"`）+ `alertLevel` + `alertMessage`。

## 如何新增一台醫療設備（例：病患監視器 monitor, Unit 3）

**後端**
1. 在 `simulator/profiles_medical.go` 仿照 `NewInfusionPump()` 寫一個 `NewPatientMonitor()`，定義 Regs（心率/血氧/血壓…）、Coils、Failures（如 `flatline`）、Attacks（如竄改警報閾值）、Physics。
2. `facility/registry.go` 的 `BuildAll()` 加一行 `simulator.NewPatientMonitor(),`（Unit 3）。
3. 若要 CTF，`flags.go` 加 `"monitor": {...}`。

**前端**
4. `frontend/src/facilities/profiles.ts` 加一個 `MONITOR` FacilityProfile（core/derived/coils/attacks/failureMessages，鍵/閾值要跟後端對齊），並加進 `FACILITY_PROFILES` 與 `FACILITY_ORDER`。
   - 只做到這裡，前端就會用「通用遙測孿生」把它顯示出來（HUD 全部自動生效）。
5. （選配）想要專屬 3D：仿 `InfusionScene.tsx` 寫 `MonitorScene.tsx`，在 `scene/Scene.tsx` 的 dispatch 加一個分支。3D 場景慣例見既有兩個 Scene 檔（`M()` 材質切換寫實/示意、`useFrame` 內 `usePlantStore.getState()` 讀值、`instancedMesh` 做粒子）。

**驗證**：`cd backend && go build ./...`；`cd frontend && npx tsc --noEmit && npm run build`。

## 如何新增一個協定 fuzz 標的

在 `medproto/` 加一個 `xxx.go`，暴露 `func StartXXX(addr string) error`（阻塞式 accept loop），在 `main.go` 用 goroutine 起它並加一個埠旗標。務必：一個 conn 一個 goroutine、`defer recover()`、bound 讀取長度、設 read deadline——這樣畸形輸入才不會弄垮整個 process。可參考 `medproto/hl7.go`。

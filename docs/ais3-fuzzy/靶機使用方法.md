> **安全聲明：** 僅限隔離實驗室。病患／影像／設備皆為合成資料；禁止連接真實醫院網路或真實醫療設備。本倉庫**不含** CALDERA Server。

---

## 1. 這座靶機在做什麼

用 Docker Compose 模擬迷你虛擬醫院：廠商入口 → 醫療工程站 → HL7／RIS／PACS／FHIR／BACnet → MRI。  
演示者可手動跑攻擊鏈，或之後自行掛 CALDERA Agent。

| 目標 | 說明 |
|---|---|
| 攻擊前有基線 | Reset 後 MRI 為 `READY`、冷卻 `NORMAL` |
| 攻擊後可觀測 | 醫囑錯配、TEST 影像、越權查詢、MRI `PROTECTIVE_STOP`、協議工具箱癱瘓 |
| 可重複 | `POST /reset` 重播同一套 Seed |

---

## 2. 環境需求

- Docker Desktop（或同等 Docker Engine + Compose v2）
- 建議可用記憶體 ≥ 8 GB（HAPI FHIR 較吃資源）
- macOS／Linux／Windows（WSL2）皆可；下文以本機 `127.0.0.1` 為例

---

## 3. 啟動與停止

```bash
cd lab
cp .env.example .env          # 第一次
docker compose up -d --build
```

等約 1–3 分鐘（尤其 `ehr-fhir`）。確認：

```bash
docker compose ps
./scripts/smoke-test.sh       # 就緒自檢 + Reset + 基線驗證
```

停止：

```bash
docker compose down           # 停容器
docker compose down -v        # 連 volume 一併清除
```

---

## 4. 場景狀態頁（建議常開）

瀏覽器開啟：

```text
http://127.0.0.1:8100
```

等角俯視圖會輪詢各設施狀態：

| 畫面狀態 | 含義 |
|---|---|
| 綠／ONLINE／READY／NORMAL | 正常 |
| 紅／ALARM／PROTECTIVE_STOP | 攻擊或聯鎖異常（如 BACnet→MRI） |
| 紅／PARALYZED | 協議工具箱 CLI 被癱瘓（軟癱瘓時 SSH 仍可能通） |
| 灰／OFFLINE | 探測不到（服務掛了或硬癱瘓停 SSH） |

快捷連結可開 Orthanc、FHIR、各 API；此頁為**觀測用**，不是攻擊面。

---

## 5. 建議操作流程（第一次）

```text
啟動 compose
  → smoke-test（確認基線）
  → 開場景頁 8100
  → attack-manual-demo（完整攻擊鏈）
  → 觀察 MRI／冷卻變紅
  → （可選）癱瘓協議工具箱
  → POST /reset 回到基線
```

## 6. 腳本一覽

| 腳本 | 作用 | 會不會改場上狀態 |
|---|---|---|
| `./scripts/smoke-test.sh` | 就緒檢查、SSH 橫向、Reset、驗證基線 | 會 Reset |
| `./scripts/attack-manual-demo.sh` | 完整手動攻擊鏈（不需 CALDERA） | 會留下攻擊效果 |
| `./scripts/attack-paralyze-protocol-runner.sh` | 癱瘓／還原協議工具箱 | **只動** protocol-runner |
| `curl -X POST http://127.0.0.1:8099/reset` | 全場回到 Seed 基線 | 清攻擊效果；**不還原**工具箱癱瘓 |

### 6.1 自檢（smoke）

```bash
cd lab
./scripts/smoke-test.sh
```

通過條件包含：vendor→biomed SSH、憑證存在、Reset 成功、Worklist／MRI READY／PACS／FHIR 基線、未授權被拒。

### 6.2 完整攻擊鏈

```bash
cd lab
./scripts/attack-manual-demo.sh
```

步驟：

1. SSH 橫向 `vendor-entry` → `biomed-ws`，讀取過寬 Token  
2. HL7 醫囑錯配／重送（Worklist 出現錯 PID／重複 accession）  
3. DICOM 測試 C-STORE（`TEST-ATTACK-001`）  
4. DICOMweb／FHIR：過寬可廣查、窄 scope 被拒  
5. 真 BACnet WriteProperty → 冷卻 `ALARM` → MRI `PROTECTIVE_STOP`

> 若先前癱瘓了協議工具箱，請先還原再跑攻擊鏈（DICOM／BACnet 步驟會呼叫 runner CLI）。

### 6.3 癱瘓協議工具箱

```bash
# 癱瘓 → 驗證 → 自動還原（測試用）
./scripts/attack-paralyze-protocol-runner.sh

# 癱瘓後維持（演示用）
./scripts/attack-paralyze-protocol-runner.sh --leave

# 硬癱瘓：連 SSH 停掉（場景頁可能變 offline）
./scripts/attack-paralyze-protocol-runner.sh --hard --leave

# 只還原工具箱
./scripts/attack-paralyze-protocol-runner.sh --restore
```

**重要區分：**

| 指令 | 協議工具箱 | MRI／冷卻／醫囑錯配等 |
|---|---|---|
| `--restore`（工具箱腳本） | 恢復 CLI | **不變**（紅的還是紅的） |
| `POST /reset` | **不**自動恢復癱瘓 | 清回基線（MRI READY 等） |

兩邊都還原才算「全場乾淨」：

```bash
./scripts/attack-paralyze-protocol-runner.sh --restore
curl -X POST http://127.0.0.1:8099/reset
```

## 7. 手動連線與觀測

### 7.1 SSH（Host 映射）

```bash
cd lab

# 廠商入口（初始據點）
ssh -p 2221 vendor@127.0.0.1
# 密碼：Vendor@123

# 醫療工程站
ssh -p 2222 biomed@127.0.0.1
# 密碼：Vendor@123

# 協議工具箱
ssh -p 2223 runner@127.0.0.1   # 密碼 Runner@123
```

容器間共用的實驗 SSH 私鑰由 `lab-keys` named volume 在啟動時
產生，只供靶場橫向連線使用，不會寫入 Host 專案目錄。

容器內橫向（V-02）：

```bash
# 在 vendor-entry 上
ssh biomed@10.77.20.10
cat /opt/hospital/creds/endpoints.env
cat /opt/hospital/creds/fhir.token
```

### 7.2 常用 HTTP 觀測

| 用途 | URL |
|---|---|
| 場景頁 | http://127.0.0.1:8100 |
| Orthanc | http://127.0.0.1:8042 （Basic：`overprivileged`／過寬 token） |
| FHIR | http://127.0.0.1:8180/fhir （需 `Authorization: Bearer …`） |
| MRI 狀態 | http://127.0.0.1:8090/status |
| BMS 冷卻 | http://127.0.0.1:8091/cooling |
| Chiller | http://127.0.0.1:8092/status |
| 協議工具箱狀態 | http://127.0.0.1:8093/status |
| Reset | `POST http://127.0.0.1:8099/reset` |
| Worklist | http://127.0.0.1:8085/worklist |

範例：

```bash
curl -sf http://127.0.0.1:8090/status
curl -sf http://127.0.0.1:8091/cooling
curl -sf -u overprivileged:lab-dicomweb-token-overprivileged \
  http://127.0.0.1:8042/studies
curl -sf -H 'Authorization: Bearer lab-fhir-token-overprivileged' \
  'http://127.0.0.1:8180/fhir/Patient?_count=20'
curl -sf -X POST http://127.0.0.1:8099/reset
```

### 8.2 Token（刻意弱點）

| 用途 | 憑證 | 能力 |
|---|---|---|
| FHIR 過寬 | `Bearer lab-fhir-token-overprivileged` | 廣查合成 Patient |
| FHIR 窄 scope | `Bearer lab-fhir-token-patient001` | 僅 `patient-001` |
| DICOMweb 過寬 | Basic `overprivileged` / `lab-dicomweb-token-overprivileged` | 廣查 studies |
| DICOMweb 窄 scope | Basic `scoped` / `lab-dicomweb-token-patient001` | 需 `PatientID=patient-001` |

實體檔在 biomed：`/opt/hospital/creds/`。

## 9. 與 CALDERA

- `vendor-entry`（hospital-entry）
- `biomed-ws`（hospital-biomed）
- （可選）`protocol-runner`（hospital-protocol）

## 10. 常見問題

**Q：還原協議工具箱後，MRI／冷卻還是紅的？**  
A：`--restore` 只還原 CLI。請再執行 `POST /reset`。

**Q：Reset 後協議工具箱還是 PARALYZED？**  
A：Reset **不會**清工具箱癱瘓。請跑 `--restore`。

**Q：攻擊鏈在 DICOM／BACnet 失敗？**  
A：多半是工具箱仍癱瘓；先 `--restore` 再跑 `attack-manual-demo.sh`。

**Q：smoke-test 一直等 FHIR？**  
A：首次拉映像與 HAPI 啟動較慢，可 `docker compose logs -f ehr-fhir`；確認後再跑 smoke。

**Q：場景頁協議工具箱仍顯示正常，但 CLI 已拿掉？**  
A：請確認已重建含 `/status`（8093）的版本；軟癱瘓應顯示 `PARALYZED`／告警。重整瀏覽器快取。

**Q：如何確認當前狀態？**  

```bash
curl -sf http://127.0.0.1:8090/status
curl -sf http://127.0.0.1:8091/cooling
curl -sf http://127.0.0.1:8093/status
curl -sf http://127.0.0.1:8100/api/snapshot | python3 -m json.tool | head
```

## 11. 演示檢查清單

1. `docker compose up -d` 且 `./scripts/smoke-test.sh` 通過  
2. 場景頁 http://127.0.0.1:8100 可開，MRI 為 READY  
3. `./scripts/attack-manual-demo.sh` 通過，場景頁 MRI／冷卻變紅  
4. （可選）`--leave` 癱瘓工具箱，場景頁顯示 PARALYZED  
5. `--restore` + `POST /reset`，再次 smoke 通過，可重複演示
